Як перевірити та встановити дотнет
1) Перевіряємо наявність дотнету:
dotnet --version
2) Якщо дотнету немає встановлюємо його:
Windows:
simply variant: завантажити з офіційного сайту https://dotnet.microsoft.com/en-us/download
winget: відкриваємо PowerShell і прописуємо команду: winget install Microsoft.DotNet.SDK.<version_number:int>

Linux(Ubuntu):
sudo apt-get update && \
  sudo apt-get install -y dotnet-sdk-10.0

Як створити проєкт ASP.NET

Для створення пустого проєкту викликаємо команду:
# створює пустий проєкт лише з одним простим ендпоінтом 
# за замовчуванням включений Top-level statements
dotnet new web -n <project_name> 

// Program.cs:
using Microsoft.AspNetCore.Builder;

// Файл старту, тут запускається сервер

// як запустити ASP проєкт
// # запуск проєкту 
// dotnet run 

// Запуск у режимі Hot Reloading(якщо ASP бачить якісь зміни одразу пропонує перезавнатжити)
// dotnet watch run

// відновити пакети, якщо виконуєте перенос на інший пристрій
// dotnet restore 

namespace p48_lessons_asp
{
    public class Program
    {
        public static void Main(string[] args)
        {
            var builder = WebApplication.CreateBuilder(args);
            var app = builder.Build();

            app.MapGet("/", () => "Hello World!");

            app.Run();

        }
    }
}

// Ctrl+K, Ctrl+F - formatrting code


як запустити ASP проєкт:
# запуск проєкту 
dotnet run 

# запуск проєкту у режимі Гарячого Перезавантаження(Hot Reloading)
# у такому режимі, включається спеціальний наглядач, який бачить зміни файлів
# як тільки змінюється файл, він одразу перезавантажує сервер
dotnet watch run

2. Структура проєкту
Окрім Program.cs створються додаткові файли:
- <project_name>.сsproj - файл конфігурації проєкту, тут задається:
    - версія дотнет
    - тип проєкту
    - інформація про nuget-packages(додаткові бібліотеки)
- appsettings.usage.json - конфігурація додатку(~.env)
    - рядки підключення до бд
    - налаштування логеру
    - апі-ключі
    -! У проєкті їх може бути декілька версій, наприклад один файл використовується
    під час розробки. Інший файл у продакшені і тд.
- Properties/launchSettings.json - профілі запуску проєкту:
    - налаштуваня порта, на якому сервер буде слухати запити
    - змінити Kestrel на IIS-Express 
    ! профілі потрібні тільки для локального запуску(у розробці), у продакшен цей файл не йде

3. Статичні файли та їх налаштування:
Статичні файли у контексті веб-додатка -- це файли які зберігаються на сервері, вони ніяк не змінюються. Клієнт їх може запитати, і вони завжди будуть повертатися в одному і тому самому форматі без змін. Наприклад - html-документи, стилі та скріпти для цих документів, картинки, гіфки.

В ASP.Net для цих файлів необхідно створити спеціальну директорію під назвою wwwroot.
Саме з цієї папки сервер роздає статичні файли.

Так само потрібно налаштувати додаток, необхідно підключити два мідлвеєри:
! ВАЖЛИВИЙ МОМЕНТ: усі мідлвеєри, підключаємо до створення рутінгу
- Мідлвеєр який дозволяє шукати файли у проєкті: app.UseDefaultFiles();
- Мідлвеєр який включає роздачу статичних файлів сервером: app.UseStaticFiles();
