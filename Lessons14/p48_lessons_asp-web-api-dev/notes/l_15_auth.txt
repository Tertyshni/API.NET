Типи авторизації
Session-based - сесійна авторизація на базі Cookie. Основа для монолітних додатків (SSR)
- Як це працює: Користувач вводить логін та пароль. Сервер перевіряє правильність даних, знаходить користувача у базі даних, створює запис у базі даних
з унікальним SessionId, При кожному запиты, браузер автоматично прикріплює куку, а сервер звіряє її зі сховищем.
Їх можна легко відкликати, сесію можна видалити з БД, дані користувача на клієнті не зберігаються

Token-Based session - авторизація яка працює на токенах, сьогодні є стандартом для SPA, мобільні додатки та мікросервіси.
- Як працює: автентифікація через логін та пароль, сервер так само перевіряє ці дані, і генерує спецальний токен наприклад JWT(JSON Web Token) - 
криптографічно підписаний рядок, який містить корисне навантаження(ID користувача, роль, та час життя токену). Сервер як правило не зберігає цей токен, клієнт зберігає токен і передає його
у кожному запиті в загловку: Authorization: Bearer <token>. Сервер просто перевіряє математичний підпис токена, за допомогою секретного ключа

Basic Auth- найпростіший метод, вбудований у HTTP-протокол. Логін та пароль об'днуються через двокрапку(логін:пароль) і кодуються у Base64. Для роботи з таким способом авторизації
Обов'язкове використання HTTPS, оскільки кодування != шифрування. Передаються заголовком  Authorization: Basic <base64>.

ApiKeys - довгий випадковий рядок, який видаэться розробнику або ыншому сервісу, як правило в заголовку X-API-Key або queryParams. Ідентифікує не людину, а якийсь сервіс, додаток тощо

Делегована авторизація
OAuth 2.0 - це протокол авторизації, який дозволяє одному сервісу отримати обмежений доступ до ресурсів користувача на іншому сервісі без передачі пароля
